## 単段ロケットの実行

```sh
cargo run --release --features optimization --bin openTsiolkovsky-optimize -- \
  --config examples/optimization/momo_single_stage.json --output /tmp/momo-opt.json
```

MOMO Flight 3のリポジトリ内モデル `examples/momo.json` をインラインで収録した。
これは実在機を基にした3DoFモデルの数値実証であり、追加ペイロード能力や設定した荷重上限を実機仕様として認定するものではない。

| 項目 | 設定・扱い |
| --- | --- |
| 質量 | 基体1,150 kg = 基体乾燥282.9638783 kg + 搭載推進剤867.0361217 kg。追加ペイロードpは別に初期質量へ加え、燃焼・惰行の全期間で運ぶ |
| エンジン | 真空15,183 N / 207.14 s、0〜116 s固定燃焼。質量流量は真空推力/(Isp g0)、実推力には出口面積×周囲圧力を差し引く |
| 残量 | 燃焼で867.023629599 kgを消費。約0.012492101 kg残る。0.01 kgの数値試験用予備量を要求する |
| 初期状態 | 元のMOMO設定のWGS84位置、地球自転を含むECI速度。レールなし、地球相対初速度0 |
| 制御・設計変数 | 最初の5 sは垂直固定、射向112.5°固定。以後のNED仰角、追加ペイロード0〜100 kg、惰行時間60〜180 sを最適化 |
| 惰行 | 同じ段・同じ質量で推力0、既存の `aero_stable` モード。燃焼と惰行の境界で位置・速度・質量をリセットしない |
| 目的 | 追加ペイロードを最大化。基体乾燥質量に元から含まれる搭載物を、正味衛星質量と呼ばない |
| 終端 | WGS84測地高度100,000 m、NED鉛直速度0。発射地点の射向へ投影したECEF変位が10,000 m以上。投影距離は大円距離ではない |
| 荷重上限 | 動圧50,000 Pa、迎角5°、比力60 m/s²。比力は重力を除く推進・空力の合力ノルム/質量 |
| 制御上限 | 燃焼中の仰角30〜90°、仰角レート±0.5°/s、区間境界で仰角連続。姿勢運動・TVC応答の実現性は別途検証が必要 |

既存の座標変換、J2重力、USSA大気、風、CA/CN-alpha、圧力損失、燃料消費を共有する。
局所ADは各ノードの状態7成分・仰角・時刻の9方向。LGRの線形項、区間長、
初期質量とペイロードの結合、制御の連続性・レートは解析的に組み立てる。
ECI位置は発射点を原点として100 kmで、速度は1 km/s、質量は基体湿潤質量、
時間は燃焼時間で尺度化する。目的の尺度は100 kg。これらは`flight_scaling`に保存する。

迎角は前向き円錐 `u >= 0, u² >= cos²(alpha_max) |v_air|²` として課す。
第2残差は正の `|v_air|² + (10 m/s)²` で割る。これは物理的な迎角上限を変えず、
離床直後に微小速度で割ることによる悪条件を避ける尺度化である。
制御は右LGR点の次数N-1多項式で、初期端を明示的に外挿する。
Bernstein係数の包絡で多項式全体の仰角とレートを制限する。この条件は十分条件であり、
同じ物理上限を満たす多項式の一部を保守的に除外しうる。密な再積分でも再評価する。

初期推定は既知の最適解を使わず、`initial_pitch_end_deg`へ滑らかに傾ける制御を
初期ペイロード・惰行時間でRK45積分して作る。ペイロードや惰行時間の上下限を一致させれば固定できる。
最初の実装は正の一定推力/Isp、燃焼開始0 s、単段・CN-alpha・aero_stable惰行に限定し、
レール、分離、投棄、トリム、外部CSV等の未対応入力を明示的に拒否する。
惰行の`aero_stable`は空気流へ瞬時に整列する既存3DoF近似であり、燃焼停止時の姿勢遷移や惰行中の角速度は制約していない。
ZEROの軌道投入・多段最適化の代わりにこのケースを表示しない。

`validation.flight`にSI制約台帳、質量内訳、再積分サンプル、状態多項式との差、
10倍厳しいRK45との差を保存する。初期状態から1本のIVPとして積分し、
各区間60分割とLGR点・境界両側で検査する。区間境界は両側で同じ式から時刻を作る。
物理許容差は入力`validation`に明記する（例: 位置5 m、速度0.05 m/s、質量0.001 kg）。
動圧等の密な標本検査は連続時間の厳密証明ではない。

`momo_single_stage_coarse.json`は求解が収束しても再積分が不合格になる例。
画面の「メッシュを細分化して再実行」は物理設定・制約・許容差を維持して新しい実行を作る。
自動で制約を緩和したり、不合格の途中解を成功へ変えたりしない。

## 多段ロケットの実行

```sh
cargo run --release --features optimization --bin openTsiolkovsky-optimize -- \
  --config examples/optimization/two_stage_500km_43deg.json --output /tmp/two-stage-opt.json
```

**仮定した機体による数値実証**であり、ZEROの質量・推進系・性能を表す入力ではない。
目標はペイロード分離直後の接触円軌道 `r = 6,378,137 + 500,000 m`、傾斜角43°。
WGS84測地高度は大気とクリアランスに使い、軌道高度と区別する。
目的は初期全質量に加えた正味衛星質量で、PAF 150 kgとフェアリング1,000 kgは別計上する。

| 項目 | 第1段 | 第2段 |
| --- | --- | --- |
| 乾燥 / 搭載推進剤 | 13,000 / 165,000 kg | 4,000 / 40,000 kg |
| 真空推力 / Isp | 3,200,000 N / 300 s | 450,000 N / 350 s |
| 最大累積燃焼 / 予備推進剤 | 145 s / 1,000 kg | 300 s / 500 kg |
| 最大着火回数 | 1 | 2 |

いずれも数値実証用の仮定値。各在庫に`source`、問題に`data_source`を必須とする。
第1段は10 sの垂直上昇と135 sの誘導燃焼、停止から3 s後に分離する。
第2段は分離から5 s後に着火し、最初の燃焼終了時にフェアリングを投棄する。
続く惰行と第2回燃焼の長さを最適化し、最終停止時にΔv=0で衛星を分離する。
停止と衛星分離の間隔はこの例では0 s。間隔が必要なら最後に惰行フェーズを追加して
その終了イベントを`deploy_payload`にする。段数は2〜4、イベント順序・着火回数は固定する。
各フェーズの`duration_s.lower`は最短燃焼・停止間隔にもなる。混合比・推進剤沈降・
電力/熱資源による再着火可能性を評価したものではない。

`vehicle.stages[].engine.burn_end_s`は当該段の最大累積オン時間と一致させる。
一定の正の真空推力/Ispを使い、実際のオン/オフとイベント時刻は`phases`が決める。
既存シミュレータの`separation_time_s`等で最適化中にモードを切り替えない。
圧力損失・空力・地球回転・J2・USSA大気は共有評価関数を使う。
全飛行で`attitude_program`とし、惰行でも同じ機体軸から空気力を評価する。
投棄後は参照面積を明示した係数で変更する。露出ペイロードの熱解析にはならない。

状態は区間ごとに独立して保持し、7成分の接続式を明示する。
分離時には `乾燥質量 + 搭載推進剤 - 累積消費量` を引き、位置・速度を連続にする。
フェアリング、最終段残量、PAFも別に引く。残存機体の質量を公称値で上書きしない。
各段の消費量上限・予備量・着火回数を課し、衛星分離後の質量が正味衛星質量になることを確認する。

NEDの方位角・仰角は燃焼中にLGR多項式で最適化する。惰行中はフェーズ全体で
角度が線形に変化する制御に限定する。高真空中で力に効かない高次制御の自由度を減らすための
明示的な制御族の制限であり、一般の惰行姿勢を探索するものではない。
全境界で角度を連続にし、Bernstein包絡の角度/成分レートに加え、NED基底の移動を含む
実際のECI機体軸の変化率を局所ADと独立再積分の両方で検査する。

`validation.multi_stage`には段別在庫、独立に積分した消費量、イベント左右の状態、
投棄内訳、投入軌道、密なSI制約台帳を保存する。11状態のRK45は元の7状態に4段分の
累積消費量を加え、**再積分で得た実消費量**を使って投棄する。開始時やイベント後に
NLP状態へ戻さない。各区間60分割・LGR点・イベント両側、さらに10倍厳しいRK45で照合する。
同じ式の時間積分と局所ADを別経路で検査し、誤った残存質量を1 kg加えた試験も検出する。

この数値実証では熱流束/積算熱、落下域、相対分離運動、TVC/6DoF、沈降/再着火資源は
`unevaluated_constraints`として明示する。高度100 km以上というフェアリング条件だけで
熱条件を満たしたとは判定しない。計画PR 5aの熱を含む全範囲やZERO基準ケースは未完了。

## Nativeでの実行

```sh
cargo run --release --features optimization --bin openTsiolkovsky-optimize -- \
  --config examples/optimization/hs071.json --output /tmp/hs071-result.json
cargo run --features optimization --bin openTsiolkovsky-optimize -- \
  --config examples/optimization/zero_500km_43deg.json --check
```

HS071は4変数・2制約の既知解問題。目的値は約17.014017289、変数は約
`[1, 4.74299964, 3.82114998, 1.37940829]`。実機の性能試験ではない。
ZEROの500 km円軌道・43°プリセットは、LC-1位置、打上げUTC、質量内訳、機体制約等が
未設定のため意図的に実行できない。`--check`は不足項目をJSONで返し終了コード3となる。
未設定値を0や無制約へ置換しない。
`--schema`で最適化専用のJSON Schemaを出力できる。終了コードは0=成功、1=求解/検証/IO失敗、2=引数誤り、3=入力不正または未設定。

```sh
cargo run --release --features optimization --bin openTsiolkovsky-optimize -- \
  --config examples/optimization/double_integrator.json --output /tmp/trajectory-result.json
```

二重積分器は `x'=v, v'=a`、静止状態から1000 m先の静止状態への移動で、
`J=∫a²dt + 3600 T` を最小化する。重力・空力・推進剤を含まない解析用問題である。
固定時間の最適制御は `a(t)=6d/T²(1-2t/T)`、`J=12d²/T³+3600T`。
自由時間の最適値は `T=(36d²/3600)^(1/4)=10 s`、目的値48,000 m²/s³。
入力例の初期値12 sでの物理尺度を求解中は固定するため、TNLP尺度の目的値は82.944。
初期推定は線形位置・速度0・制御0とし、解析解を初期値へ埋め込んでいない。

状態は各区間の左端と右LGR点、制御は右LGR点だけに置き、隣接区間の端点状態を共有する。
4区間×次数4を例とし、終端時刻は上下限を同じ値にすると固定できる。
入力・状態・時間・制約の微分は解析式。非線形なロケット物理を有限差分で代用する実装は追加していない。

入力・結果は独立した`schema_version: 1`。pounce一式は0.12.0に固定する。
目的・制約の尺度と検証許容値は別に扱う。HS071は単位尺度、
`nlp_scaling_method=none`、KKTは上流既定、HessianはL-BFGS。
採用版は内部のcold retryを持つため、`presolve`、`l1_fallback_on_restoration_failure`、`mu_strategy_fallback`、`dual_divergence_retry`を明示的に無効にし、実効オプションへ記録する。復元フェーズは通常の内点法の一部として接続する。
結果は全主変数、上下限乗数、全制約値・乗数、変数/制約名、反復履歴、入力、
実効オプション、ソルバー版、ビルド時のcommit SHA（未コミットのコード変更は`-dirty`）を保存する。
`nlp_layout`には初期値、上下限、疎ヤコビアンの位置も保存する。主・双対変数はTNLP座標であり、SI感度への逆変換は後続とする。
配布ソースにGit情報がない場合はビルド時の`OPENTSIOLKOVSKY_REVISION`で指定できる。

終了コード0には`Solve_Succeeded`と数値検証合格の両方が必要。
反復上限・中断・許容精度での終了は成功扱いしない。結果JSONは診断用に保存する。
`solver.stop_after_iteration`は中断経路を再現するための設定で、0なら最初のcallbackで停止する。
ソルバーの実行不能判定は、非凸問題に解が存在しないという数学的証明を意味しない。

## 再積分と数値検証

二重積分器はLGR制御多項式を復元し、初期端点の制御を明示的に外挿する。
指定された初期状態からRK45で前進し、区間境界で厳密に停止する。
後続区間を最適化ノードの状態でリセットしない。ノードと各区間20分割の検査点で
状態多項式との位置・速度差を検査し、制御エネルギーも別状態として再積分する。
RK許容値をさらに10倍厳しくした計算との差、解析的な時刻・目的値との誤差も保存する。

`try_advance_to`は状態成分別の絶対許容値、相対許容値、最小/最大刻み、反復上限を持つ。
最小刻みで精度未達なら時刻も状態も進めずエラーとし、中間段の非有限値もエラーにする。固定長配列により状態/微分の次元は型で一致させる。
最新の固定長配列・FSALカーネルを共有する。既存シミュレータの`advance_to`は強制採択/警告の仕様を維持する。旧`integrate_with_outputs`は最新構成に存在しない。
単段の燃焼→停止→惰行に加え、多段の分離・フェアリング投棄・上段再着火・衛星分離の固定イベント列を検証した。
密な検査点の合格は連続時間のパス制約保証を意味しない。

## ブラウザでの実行

```sh
rustup target add wasm32-wasip1
bash scripts/optimization_wasm_build.sh
cd frontend
bun install
bun run dev:optimization
```

ヘッダの的のアイコン「軌道最適化」から専用ワークスペースを開く。日本語/英語とテーマは現在のアプリに従う。初期ケースは仮定した2段機であり、ZERO実機の諸元ではない。

1. **設定**でミッション、発射条件、段別の乾燥・推進剤・予備量、エンジン、フェーズ時間、制約、メッシュと検証許容値を編集する。全備質量は内訳に同期する。予備量は搭載推進剤の内数。時間やペイロードの上下限が等しければ固定、異なれば最適化する。設定のタイムラインは初期推定時刻を表示する。
2. **最適化を実行**すると入力コピーを固定し、別Workerで求解・独立再積分する。入力不備や数値の空欄は実行前に示す。空欄を0へ変換しない。実行中は設定を固定し、進捗は反復数・目的値・NLP制約残差で示す。中断したWorkerのメッセージは後続結果へ混入させない。
3. **結果**では求解の収束と数値検証を別々に表示する。SI値の比較、質量収支、分離イベント、再積分時刻のタイムライン、フィルタ可能な制約台帳、尺度・主双対変数・実効オプション・コード版を確認できる。地図は記録された本体のECI位置と分離位置を表示し、時間カーソルをグラフと共有する。対応する制約の位置アイコンから再積分サンプルでの極値時刻へ移動できる。分離物の落下軌道やIIPは生成しない。
4. **保存した実行**から結果を復元、比較対象に指定、入力として再編集、全結果JSONで保存できる。履歴検索と可逆なアーカイブを持つ。入力の下書き（未入力の数値を含む）と全結果はIndexedDBへ自動保存する。ブラウザのサイトデータを削除すると失われるため、共有・バックアップにはJSONを使う。保存失敗時は画面で知らせ、下書きは同じタブ内にも保持する。

「JSONを読み込む」またはダイアログへのドロップで、入力JSONと全結果JSONの両方を読める（64 MiBまで）。不正なファイルは現在の設定・結果を残して拒否する。結果読込は記録の表示であり、再求解や再検証ではない。元の実行ID・コード版・全主双対ベクトルを保持し、同じ実行IDのファイルを複数読んでも別の保存記録として扱う。最適化ダイアログを閉じた場合は、既存シミュレータのファイル操作へ戻る。

比較はSIのペイロード・軌道・再積分誤差等を並べ、物理設定が異なる場合は警告する。メッシュや初期推定の違いを許す比較でも、入力と尺度は診断画面で確認する。実行時入力のserde既定値と、編集時に省略された同じ既定値は、比較時だけ同一として扱う。入力JSON自体を補完・変更しない。

結果の地図上でも通常のホイールはページのスクロールに使い、Ctrl/⌘＋ホイールで地図を拡大縮小する。ドラッグによる地図操作と時間スライダーは併用できる。

段数・イベント順序・推力テーブル等、フォームにない設定は「JSON・詳細」で保持・編集する。新しい物理モデル、任意式の編集、分離物の落下域、warm start、S1の厳密Hessian/尺度実験はこのUI実装の対象に含めていない。メッシュ細分化は新しい実行として保存し、入力は選択中の結果に記録されたものを使う。

フォームの構造検査はRustの`--schema`から生成した`frontend/src/lib/optimization-schema.json`を利用する。入力型を変更した場合は次で再生成し、フォームの型・検査・例を更新する。Rust側の入力検査を最終的な判定とする。

```sh
cargo run --release --features optimization --bin openTsiolkovsky-optimize -- \
  --schema > frontend/src/lib/optimization-schema.json
cd frontend
bunx vp check --fix
bunx vp test run
```

既存wasm-bindgenシミュレータと別の`wasm32-wasip1`モジュールをビルドする。
長さ付きUTF-8 JSON ABIと小さなWASI shimで通信し、求解と検証はWorker内で実行する。
中断方式は`worker.terminate()`を選択した。COOP/COEP・SharedArrayBufferは不要で、
途中の解は失われる。callbackによる協調停止はnative/WASIの試験設定で検証済み。
反復分割によるwarm startやSharedArrayBuffer方式の性能比較は未実施。
ファイル操作用WASIインポートにはエラーを返し、環境変数も渡さない。
`clock_time_get`、`fd_write`、ハッシュ用乱数等、採用版の実際のインポートをテストで確認する。

## 回帰の実行

```sh

python3 scripts/verify_multi_stage.py

bunx vp test run
bun run build
```

WASI試験はブラウザと同じshimを使い、nativeに対する全主双対ベクトル、目的値、
終了理由、検証合否、中断・反復上限・入力エラー・再実行を確認する。
多段の主変数はSI単位で比較する。上限は成分位置2 m、速度0.005 m/s、質量/正味衛星0.001 kg、
角度0.01°、時間0.001 s。全等式と有効な不等式の値、上下限乗数は相対2e-5、
制約乗数はTNLP尺度で相対3e-4とする（相対分母の下限1）。非有効不等式の値は
一致を要求せず、全要素の有限性・上下限と独立再積分の合否を検査して最大差を保存する。
この問題ではRAAN/軌道上位相が自由であり、高次制御係数や非有効Bernstein包絡の値が
同一になるとは限らない。全入力・全結果・比較値は`out/optimization/wasm-parity/`に残す。
製品ビルドをローカル配信し、ブラウザで単段の求解合格、粗メッシュの不合格と細分化後の合格、Worker中断・再実行、既存MOMO（最高高度113.0 km）画面への復帰を確認した。ブラウザの警告・エラーログは0件。ZEROの未設定検出はnative/WASIで継続確認する。
