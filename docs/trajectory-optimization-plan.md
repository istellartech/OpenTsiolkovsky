# 軌道最適化の設計計画

更新: 2026-10-19。この文書は目標と設計要件を定める。[実装済み範囲・次の作業](trajectory-optimization-status.md)、[操作方法](optimization.md)、[数値仕様と比較結果](optimization-numerics.md)は各文書を参照する。

## 1. 目標

OpenTsiolkovskyの物理を使い、ブラウザ内で多段ロケットのペイロード最大化軌道を求める。

| 項目 | 方針 |
| --- | --- |
| 基準ミッション | 2段の小型ロケット、500 km円軌道、傾斜角43°。RAAN・軌道位相は指定がなければ自由 |
| 離散化・微分 | 複数区間のflipped LGR、線形項の解析微分、物理の局所前進AD |
| NLP | pounce 0.12.0のRust TNLP、FERAL、L-BFGS既定。厳密Hessianは段階評価 |
| 実行 | 専用WASIモジュールとWeb Worker。既存シミュレータWASMは維持 |
| 合否 | 求解収束と独立再積分を別々に判定し、適用制約をSIで検査 |

### 1.1 実機データの基準ケース

- 2段機を出発点とする。段別質量・実推力/Isp・空力・運用条件は版付き機体データで与える。
- 発射点の座標・高度・射向/回廊と打上げUTCは、対象の射点の確定値を使う。別の機体の座標を流用しない。
- 軌道高度は`r_target = R_orbit_ref + 500000 m`。球基準半径の初期値は6,378,137 m。大気・地表判定にはWGS84測地高度を使う。
- 最終段停止後、衛星分離直後の接触軌道を終端とする。停止・惰行・分離は別イベント。分離Δvを導入したら分離後へ投入条件を課す。
- 正味衛星質量を目的とし、PAF・分離機構・フェアリング・上段残量は別計上する。再着火回数とイベント順序は固定する。

公開された性能値は条件・版が異なるため、500 km / 43°の正解や質量上限には使わない。43°への到達は地球回転・射向分岐・回廊を含めて確認する。データ未確定のケースは仮定した機体として表示する。

## 3. 物理問題

### 3.1 評価の境界

入力は状態・制御・設計変数、使用段/燃焼モード、絶対時刻とフェーズ開始時刻。出力は時間微分と荷重等の観測量。推力・空力・制約で別の式を持たない。定義域外・非有限値は評価失敗とし、TNLPから`false`を返す。

### 3.2 状態と制御

状態は`[m, r_ECI(3), v_ECI(3)]`、単位はSI/rad。NED方位角・仰角から機体/推力方向を指定する。垂直上昇は姿勢固定フェーズとし、方位角の特異点と±180°の折返しを避ける。必要ならECI単位方向ベクトルへ変更する。

設計変数はペイロードとフェーズ時間長。スロットルを自由化するときは、実機の範囲・変化率を守り、推力と質量流量を同時に変える。3DoFで姿勢連続・実際のECI方向レートを検査し、回転運動・TVCの実現性は外部検証へ渡す。

### 3.3 フェーズと質量

着火・停止・惰行・段分離・投棄でフェーズを区切る。微分評価中は段と燃焼モードを固定する。

```text
m_initial = m_payload + Σ(m_dry + m_propellant) + Σm_jettison
m_after   = m_before - m_dry_discarded - m_residual_discarded - m_other
r_after = r_before, v_after = v_before   # 分離インパルス0の場合
```

ペイロードは初期質量から全飛行へ効かせる。搭載推進剤・累積消費・予備量を段別に制約し、分離では実残量を引く。固定推力履歴の燃焼時間は伸縮しない。再着火/処置に必要な資源を目的から独立に確保する。

### 3.4 目的・投入・制約台帳

目的は`minimize -m_payload / F_ref`。目的専用質量尺度`F_ref`と状態質量尺度は分ける。ハード制約違反をペイロードと交換しない。

円軌道の独立な終端条件は次の4つ。`h=r×v`、`r_t=R_orbit_ref+500000`、`i_t=43°`。

```text
(r·r - r_t²)/(2r_t) = 0                [m]
(v·v - μ/r_t)/(2sqrt(μ/r_t)) = 0       [m/s]
(r·v)/|r| = 0                          [m/s]
h_z/|h| - cos(i_t) = 0                 [-]
```

RAAN/位相が自由なケースに位置・速度6成分や重複したエネルギー条件を追加しない。赤道軌道では傾斜角残差のランク退化へ対応する。許容域を最適化に使う設定と厳密な目標等式を区別し、再積分後に近地点・遠地点・傾斜角を検査する。

Cは初期投入問題の必須条件、Zは実機データ確定時の適用条件、Vは外部検証。各IDには適用域、上下限・単位、出典/版、設計余裕、数値許容差、実装/検査状態を持たせる。未実装・不足・非適用を区別する。

| ID | 区分 | 要件 |
| --- | --- | --- |
| INIT / DYN | C | 発射状態と自転速度、構成質量、並進/質量流量、下限質量・モデル定義域 |
| ORBIT | C | 指定イベント後の投入と順行方向。指定時のみ軌道面・分離時刻 |
| MASS | C | 消費・残量・予備量・投棄・正味衛星の収支。必要なら燃料/酸化剤別状態 |
| ENGINE | C→Z | 燃焼/停止時間、着火回数・間隔、連続燃焼、スロットル包絡、惰行後の始動資源 |
| CLEARANCE | C→Z | 測地高度、垂直上昇、地形・タワー・距離包絡 |
| Q / AEROLOAD | Z | 対気動圧、迎角/横滑り、qα/qβ、曲げ代理量。低速適用域とMach/高度依存上限 |
| ACCEL | Z | 非重力比力の機体軸/横の連成荷重包絡。過渡・弾性分を別途確保 |
| CONTROL | Z | 補間姿勢の連続・方向レート、NED基底の回転、スロットルレート |
| FAIRING | Z | 投棄時包絡と投棄後全区間の露出熱流束・積算熱。質量/空力/加熱モデルの切替 |
| STAGING / DEPLOY | Z | 停止・分離・着火の間隔、残量、相対分離・姿勢/角速度、上段処置資源 |
| RANGE | Z | 許容射向・回廊・落下域/IIP。分離状態から投棄物を別物体として伝播 |
| OPERATIONS | 指定時Z | RAAN/窓、通信・追跡、指定位置、日照・電力 |
| GNC / ENV | V | 6DoF/TVC余裕、構造・スロッシング、振動・衝撃・音響等 |

ユーザーズガイド類の荷重は軸/横連成の準静的包絡であり、独立の矩形上限にしない。投棄時加熱の値は自由分子流などの条件を含み、`ρv³/2`等の代理式へ直接代入しない。実機のICD・荷重配分・吸収/流れ領域を確定してから使う。

## 4. LGR転写

### 4.1 規約

```text
-1 = τ0 < τ1 < ... < τN = +1
コロケーション点: P_N(τ) - P_(N-1)(τ) の根（右端を含む）
状態: N+1点、制御: N点、D: N×(N+1)、求積重み: N点
求積: 次数2N-2まで厳密、重みは正、総和2
```

点はLegendre漸化式/Newton、Dはバリセントリック形式で作る。初期端の制御は外挿して制約・検証する。既知点、多項式微分/求積を試験する。

### 4.2 時間と接続

フェーズを複数区間に分け、区間比を固定する。自由変数はフェーズ時間長とし、開始時刻は前フェーズまでの和で作る。

```text
t_i = a + (τ_i+1)h/2
R_i = Σ_j D_ij X_j - h f(t_i,X_i,U_i,t_phase_start,p)/2 = 0
```

区間境界は状態連続、イベント境界は質量写像を適用する。大気層・テーブル折れ点付近は高次数化より区間分割を優先する。疎構造はDのブロック、ノード局所微分、自由時間の列から組む。

## 5. 微分とスケーリング

### 5.1 TNLP

変数/制約数・bounds・初期値・疎構造を固定し、値と構造の要求を分ける。`intermediate_callback`で診断と中断、`finalize_solution`で全主双対を取得する。L-BFGSでは`eval_h`を呼ばせない。

### 5.2 局所ADと自由時間

線形項・目的・時間和は解析微分、ノード物理と境界条件は小さい局所前進ADで評価する。全NLP次元の双対数を各ノードへ持たせない。同じ疎要素への寄与は加算する。以下でA=f_x、B=f_u。

```text
∂R_i/∂X_j = D_ij I - δ_ij h A_i/2
∂R_i/∂U_j =          - δ_ij h B_i/2
∂R_i/∂q = -(∂h/∂q)f_i/2
            - h[f_t ∂t_i/∂q + f_start ∂t_phase_start/∂q + f_q]/2
```

絶対時刻`t`とフェーズ開始時刻を別AD入力にする。先行フェーズの時間変更は後続の絶対時刻を動かすが、段内時刻では相殺する。複数自由時間・質量/投棄・接続を含む方向微分と疎成分を中心差分で監査する。

### 5.3 非滑らかさ

段/燃焼切替は境界へ置く。補間区間は実部で選び、区間内計算は双対数を維持する。ADは折れ点を滑らかにしないため、テーブル境界・クランプ・低速/極域は適用域と片側微分を確認する。平滑化する場合は版を分け、元モデルでも再積分する。

### 5.4 尺度と比較

アプリの変数尺度、NLPの行/目的尺度、KKT線形系を別の層とする。S0物理尺度を基準にS1 bounds/guess、S2代表ヤコビアン行補正、S3 pounce gradient-basedを比較する。実装・逆変換式・係数仕様は[数値仕様](optimization-numerics.md)に集約する。

- 物理上限とSI検証許容値を固定し、bounds・初期値・微分・主双対を同じ写像で変換する。固定幅0、無限境界、ゼロ勾配、floor/capを扱う。
- アプリ/NLP係数は1求解中に固定。フェーズ別質量尺度を使う場合も接続をSIで整合させる。短区間を理由にdefectを過小化しない。
- 小問題→単段→仮多段→実機データの順に、3初期推定・粗細メッシュ・Hessian方式を評価する。KKT none/Ruiz/slack-basedは別軸で、on-demand条件と実効動作を記録する。
- 合否、SI違反/投入誤差、性能、反復/復元、微分・因子分解時間、メモリ、全係数を保存する。m/km・kg/t・Pa/kPaで値・微分・既知解を照合する。

### 5.5 Hessian

厳密Hessianは目的と制約乗数を含むLagrangianの下三角を疎組立し、自由時間と状態/制御の交差項も含める。全NLPの有限差分二階微分は使わない。小問題の`second-order`検査とL-BFGS比較から始め、ロケットでは局所二階AD・費用・メモリを検証してから採用を決める。

## 6. 初期値・独立検証

初期値は既存制御をフェーズ別に順積分して作り、イベントをまたいで補間しない。目標へ届かない場合は明示した継続問題を使い、探索用の緩和解と最終ケースを分ける。

求解後は制御を復元し、初期状態から1本のIVPとして厳密RK45で再積分する。成分別許容値・最小刻み・有限値・反復上限を検査し、精度未達は失敗とする。イベントで停止し、NLP状態へリセットしない。

検証対象は投入、質量/投棄収支、全適用パス制約の最悪値・余裕・時刻、ノード外と境界左右、状態多項式との差、さらに厳しいRK45との差。分離物は別に伝播する。メッシュ不足は追加点/区間分割で調べ、上限緩和や自動再試行で成功へ置き換えない。

## 7. ブラウザ・入出力の要件

専用`wasm32-wasip1`をWorkerで実行し、長さ付きJSONとWASI shimで通信する。中断は`worker.terminate()`、途中解は失う。既存シミュレータのABIは維持する。

UIは編集→入力検査→求解→独立検証→SI比較→保存/再読込をつなぐ。設定にはミッション、機体/質量、フェーズ、制約台帳、数値設定を持つ。結果には収束/検証の別判定、イベント/質量、地図・グラフ、台帳の未評価、名前付き全主双対・尺度・revisionを表示する。

結果schemaには入力/データ版、メッシュ、全尺度、全解、終了理由、適用/検査状態を保存する。読込記録と新規求解を区別し、JSONで往復して設定を失わない。フォームにない構成はJSONで編集可能にする。入力不足を0や無制約へ置換しない。
