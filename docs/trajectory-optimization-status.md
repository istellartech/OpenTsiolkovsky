## 物理・数値計算側

PR 3はnative 184条件・WASI 67条件を比較した。新方式には停滞例があり、既定はS0・L-BFGSを維持する。熱・回廊・相対分離・6DoF・再着火資源は未評価。多段の系統的な検証は2段機で行っており、3/4段の実機性能の外部照合は未実施。

| 次の作業 | 確認すること |
| --- | --- |
| 誤差による区間細分化 | 多段の`initial_guess`（前回の再積分軌道をフェーズ内正規化時刻で補間）は実装済みで、ブラウザの「前回の結果を初期値に使う」と一様なメッシュ細分化で使う。残りは誤差の大きい区間だけの細分化。比較は[操作方法](optimization.md#ウォームスタートの効果2026-10-19native直列) |
| 継続法（緩和→締付け） | コールドで収束しない問題で、目標・荷重上限を段階的に締める手順と、途中解の扱い（保存しない・最終問題で再検証）を決める |
| ロケットの厳密Hessian | 局所二階AD、自由時間・接続・質量の交差項を監査。既存の1e-8停滞も調査 |
| 熱・荷重・エンジン包絡 | モデルと上限の出典・適用域を確定し、固定軌道で検証してからNLPへ接続 |
| 実機データの基準ケース | 射点座標/UTC、段別質量・推進・空力、PAF/投棄物、回廊、始動/分離条件を版付きで用意し、転写へ接続 |
| 名目外の検証 | 最適化制御を再生し、版付きの風・密度・推力・質量等のシナリオで評価 |

実機データ用の問題種別はない。データを用意しても、そのままでは転写へ接続されない。

## UI側

共通ヘッダ、ケースID・版・変換履歴、衛星/PAFの往復時の自動控除、ケースファイル/共有リンクでの内訳保持を追加した。最適化は設定と結果の並列表示（結果欄のタブに保存した実行を統合し、判定は1行の要約に圧縮）、カテゴリ別の拘束条件、地図/グラフの分割表示、独立した再生バー、PNG保存・拡大を利用できる。軌道計算のサンプルからの変換は、単段で目標頂点高度・最大動圧・惰行時間、多段で目標円軌道・荷重上限・ペイロード範囲を機体に合わせる。軌道計算の軌道と姿勢を初期推定に使い、予備量・点火遅れ・加速度の不整合を解消した。MOMO・S-310・S-520・SS-520-5・イプシロン・H-IIA・H3・ファルコン9・アリアン5・長征3B・ソユーズ・サターンVの全12種類で、調整後の既定設定から収束・独立検証合格を確認した（2026-10-21、native/WASI）。楕円軌道は待機円軌道への近似であり、実機の正式な性能検証とは異なる。[再現手順](optimization.md#サンプル機体の収束回帰)を参照。推力・qαの数値拘束そのものは未追加。

新しい物理を追加せず進められる順序は次のとおり。

1. 自動ブラウザ回帰：入力エラー、正常/不合格、中断、ウォームスタート、保存・再読込・比較、狭幅とキーボード。
2. フェーズ構成のフォーム編集：燃焼/惰行、使用段、終了イベント、追加・削除・並替え。
3. 制約の感度：ラグランジュ乗数から「上限を1単位緩めたときのペイロード増」をSIで示す（現在は上限ぎりぎりの制約を列挙するだけ）。
4. 数値診断の拡充：入力差分、NLP配置・bounds・疎構造、S0〜S3/Hessian/KKTの操作とSI乗数。

フォームにない設定はJSONで編集できる。保存記録の読込は再求解ではない。メッシュ細分化と「前回の結果を初期値に使う」はウォームスタート。地図は本体と分離位置を表示し、落下域/IIPは計算しない。
