## 3. 物理・数値計算側

### 実装と確認済みの内容

- 単段はリポジトリのMOMO Flight 3モデルを用い、100 km頂点到達時の追加ペイロードを最大化する。多段は7フェーズの仮定した2段機で、衛星分離直後の500 km円軌道・傾斜角43°を目標に正味衛星質量を最大化する。
- 多段入力は2〜4段を受理する構造だが、現在の系統的な軌道・メッシュ・native/WASIの実証ケースは2段機である。3/4段の受理と、それぞれの基準問題の検証完了を同一視しない。
- 初期質量にペイロードを加えて全飛行へ影響させる。段ごとの推進剤消費・予備量、投棄する乾燥質量と残推進剤、フェアリング、PAF、正味衛星を分けて収支を閉じる。現在の分離はインパルスなしで位置・速度を連続に保つ。
- 右LGR点の制御を復元し、初期状態から独立RK45で伝播する。後続区間を最適化ノード状態に戻さず、イベント両側と区間内の密な点で検査する。10倍厳しいRK45との照合も行う。
- 単段・多段の固定質量/時間、粗細メッシュ、複数初期推定を比較済み。多段の全146,995疎ヤコビアン成分の中心差分監査は最大規格化誤差2.33e-8。native/WASIは全解・終了理由・SI軌道・検証結果を照合している。

| 検証済みケース | 結果 | 読み取れる範囲 |
| --- | --- | --- |
| MOMO基準 | 追加ペイロード約16.89234 kg、最大位置差0.09141 m、最大速度差0.01463 m/s、収束・数値検証合格 | 固定したMOMOモデルと仮定した制約での名目数値実証 |
| 多段基準 | 正味衛星約2,557.50407 kg、近地点499,999.9987 m、遠地点500,009.6400 m、傾斜角42.999999455°、最大位置差2.00164 m、収束・数値検証合格 | 仮定した2段機の名目投入・質量収支。ZEROの性能値ではない |
| 粗メッシュ | 単段は求解収束でも検証不合格。多段は反復上限かつ検証不合格 | 求解の終了理由と物理量の再検査を分ける必要がある |
| 多段の求解許容値1e-8 | 独立検証は合格するが500反復上限。基準の求解許容値は1e-7 | さらに厳しい最適性条件での収束は未解決。検証合格を理由に収束扱いへ変えない |

数値は既存の[検証記録](optimization.md)に基づく。再現用の[単段スクリプト](../scripts/verify_single_stage.py)、[多段スクリプト](../scripts/verify_multi_stage.py)、[native/WASI照合](../scripts/test_optimization_wasm.ts)を用意している。`out/optimization/`の全結果・summaryはローカル生成物であり、リポジトリへの同梱を前提にしない。

## 5. 次に進める順序

**現在の「物理側はまだ実装しない」という方針を保つ場合は、U1 → U2 → U3 → U4を小さく区切って進める。** 各変更で既存のMOMO・仮定した多段機の入出力と合否を保つ。U2の入出力メタデータ整理は可能だが、判定対象の物理を増やす作業とは分ける。U5は対応するバックエンド機能ができるまで保留する。

物理・数値側を再開する際は、次の順序を提案する。現時点での新しい実装着手の決定ではない。

| 順序 | 作業の区切り | 検証・完了条件 |
| --- | --- | --- |
| P1 | PR 3の不足を補う。まず尺度写像・SI逆変換・単位不変性、次にS1〜S3/KKTの比較。厳密Hessianは小問題から別の区切りで比較する | 同じSI物理上限・初期軌道・予算で比較し、主双対/微分の変換と再積分を照合。1e-8停滞の原因を分けて記録し、制約緩和や自動再試行で覆わない |
| P2 | warm startと誤差に基づく区間細分化 | イベントをまたいで質量・制御を補間しない。違反/誤差のある区間を改善し、cold startとSI結果・費用を比較。単なる入力の再読込や区間数変更とは区別する |
| P3 | PR 5aに残るフェアリング投棄後の熱と、必要な荷重/エンジン包絡 | 各モデルを解析例・保存則/収支・微分・固定軌道で検証してからNLPへ接続。上限・適用域・出典・数値誤差を分けて記録 |
| P4 | PR 5bのZERO定義・実データ接続、回廊/分離物・詳細始動/分離条件 | データ版を固定し、指定された全適用条件の検査と質量収支を閉じる。V項目は外部検証の先と結果を記録。未評価があれば全要件合格にしない |
| P5 | 名目解の分散・運用条件検証と、対応UIの接続 | 最適化制御を忠実に再生し、風・密度・推力/Isp・質量・時刻等の版付きシナリオで検査。確率保証には別途分布・相関・試行数等を定義する |

ZEROの機体・運用データの整理はP1〜P3と並行して進められる。必要データの不足を理由に数値基盤の作業まで止める必要はないが、仮定した多段機の成功でZERO基準ケースの完了を代替することもできない。
